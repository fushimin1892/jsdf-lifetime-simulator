# 改正対応の手順書（俸給表・手当・賞与・退職手当）

法令が改正されたときに、決まった順番で直すための手順です。毎月の点検（クラウドの定期実行「【毎月】自衛隊シミュの改正チェック」。毎月1〜6日に起動し、その月の分が終わっていれば何もしない）もこの手順で動きます。
個々の数値がどこにあるかは [AI向け改修ガイド](AI向け改修ガイド.md) の「window.RULES の中身と根拠」を見てください。

## 守ること

- 値は公式資料（e-Gov 法令検索、官報、防衛省の国会提出法案・新旧対照表、人事院、日本年金機構、防衛省共済組合、国税庁）で確かめたものだけを入れる。確かめられないものは入れずに「未確認」と報告する。
- 人事院勧告や国会に出ただけの法案の値は入れない。公布（法律番号が付く）を確かめてから入れる。
- bot 対策でブロックされたサイトを User-Agent の偽装などで回避しない。WebFetch で 403 になる防衛省のページは内蔵ブラウザで読む。取れなければ「取得できなかった」と報告する。
- 外部ライブラリを足さない。利用者の入力を保存・送信するコードを足さない。
- 直した結果は main に commit して GitHub へ push する（GitHub Pages がそのまま公開し、パソコンの「【毎月】ローカルフォルダを最新にする」が pull で取り込む）。push の前に下の検査を全部通す。

## 役割の分け方

| 種類 | 場所 | 書くこと |
|---|---|---|
| 数値（データ） | `assets/data/pay-table.js`・`assets/data/promotion-table.js`・`assets/data/rules.js` | 法令の数値だけ。各値の横に根拠の条をコメントで書く |
| 出典 | `assets/data/sources.js`（`window.SOURCES`） | 法令ごとの e-Gov の ID・URL・記録した最新の改正、データの場所ごとの根拠の条と照合日、成立待ちのもの |
| 計算 | `assets/js/` | 計算のしかただけ。数値を書かない（`window.RULES` から読む） |
| 画面の文章 | `index.html`・`assets/js/` の説明文 | 説明文の中の数値は自動で変わらないので、数値を変えたら検索して直す。`test/check.js` の `DESC`（約40項目）が食い違いを NG にする（文言を書き換えて見つからなくなったものは「注意」と出るので、`DESC` の文言も直す） |
| 検査 | `test/check.js`（node）・`test/regression.js`（Playwright で `AI用/検証用スクリプト.js` を自動実行、期待値は `test/expected.json`） | データの形とつじつま、CSP・外部通信なし、画面の説明文の数値＝`RULES`、`lastMonthlyCheck` の日付、地域手当の経過措置の年度の表、`expected.json` と改修ガイドの hash の一致／計算結果の回帰・スマホ幅 |
| 照合の道具 | `tools/egov-check.js`・`tools/value-checks.js`（node） | e-Gov の改正日の変化の検出、俸給表・昇任表の全欄照合、手当・賞与・定年・昇任期間・退職手当・若年給付金・地域手当の数値と条文の照合 |

`assets/data/sources.js` は画面では読み込みません（サイトの動きは変わりません）。

## 毎回の流れ

1. `git status` がきれいで、main にいることを確かめる。
2. 変化を探す。
   - `node tools/egov-check.js all` … 次の4つを全部行う。
     - 改正日：e-Gov の最新の改正が `assets/data/sources.js` の記録と違う法令に「★要確認」
     - 俸給表（別表第二、全1,388欄）・昇任表（施行令 別表第一ロ、全145行）の照合
     - 数値（`tools/value-checks.js` の310項目・374組。件数は `values` の最後の「合計」の行）：手当（営外手当・指定場所生活調整金・配置手当の率・特別調整額・特殊勤務手当の区分の額と1月の上限 `monthMax`・扶養・住居・通勤・単身赴任・寒冷地・地域手当の級地と都道府県・市の表・広域異動手当の距離と割合）、賞与（期末・勤勉の割合・在職期間割合・期間率・階級加算・管理職加算）、階級（定年・昇任の最短期間・任期満了金の日数・昇給抑制の年齢）、退職手当（第3〜5条の区分ごとの支給率・減額・上限60か月・83.7％と35年・42年・調整額の半額と0の年数・調整月額）、若年給付金（20年以上・倍率・率の表の行・所得による調整の倍率）。
       照合は「区分と値の組」（例：「五箇月以上六箇月未満 百分の八十」「三百キロメートル以上 百分の十」）で行い、前後に数字が続く所には一致させない（「百分の十」は「百分の十八」に一致しない）。NG はデータと条文がずれている
     - 最後に「e-Gov で確かめられない値」の一覧が出る。これは公表資料で人が確かめる
   - 防衛省「国会提出法案」<https://www.mod.go.jp/j/presiding/houan/index.html> … 給与法の改正案の備考に「令和N年法律第N号／公布日」が付いたか。
   - 人事院 <https://www.jinji.go.jp/> … 勧告、人事院規則 9-40（賞与）・9-49／9-49-57（地域手当）などの改正通知。
3. 「★要確認」が出た法令は、改正法令の中身（新旧対照表）を読み、データに関係するかを決める。
   - 関係なければ、`assets/data/sources.js` の `egovRevision` だけ新しい値に書き換える。
   - 関係があれば、下の「種類ごとの直し方」で data を直す。
4. 直したら `assets/data/sources.js` の `items[].checked` をその日にし、`assets/data/rules.js` の `checkedOn` と改修ガイドの「最終更新」を同じ日にする（`test/check.js` が一致を確かめる）。
5. 検査する。
   - `node test/check.js` … NG 0 であること。
   - `node tools/egov-check.js all` … NG 0（直した値が条文と一致すること）。
   - `node test/regression.js` … 計算結果が `test/expected.json` と同じこと（Playwright が要る：`npm i --no-save playwright@1.61.0 && npx playwright install chromium`）。
     数値を変えたら hash は変わる。`SNAP_OUT=前.json` で直す前の全文、`SNAP_OUT=後.json` で直した後の全文を残して比べ、変わった項目が改正どおりかを確かめてから `node test/regression.js --update` で期待値を書き換え、改修ガイドの hash と初期条件の目安も同じ値にする。
   - 画面で読むファイル（`assets/css/`・`assets/js/`・`assets/data/` の画面で読むもの）を直したときは、`index.html` の `?v=` を全部新しい値にそろえる。
6. 日本語のメッセージで commit し、main を push する（例：「令和8年改正の俸給表と賞与の月数を入れる（令和8年法律第N号）」）。変更がなければ、`assets/data/sources.js` の `lastMonthlyCheck` だけをその月の日付にして commit・push する（その月の点検が終わった印）。
   - push が拒否されたら（ほかの変更が先に入った）、`git pull --rebase` のあと **5 の検査をやり直して** から push する。検査を通っていない状態で push しない。

## 失敗したときの決まり（毎月の点検）

次のどれかに当たる月は「未完了」とする。**データの変更を push せず、`lastMonthlyCheck` も更新しない**（翌日の起動で最初からやり直す）。

- e-Gov が取れなかった：`node tools/egov-check.js` の「★取得失敗」（改正の「★要確認」とは別に数える）。終了コード 3（取得できない法令があった）または 2（道具のエラー。俸給表・昇任表の取得の失敗を含む）
- 検査を実行できなかった：`node test/check.js`・`node tools/egov-check.js all`・`node test/regression.js` のどれかが最後まで動かなかった（NG が出たのとは別。NG はデータを直すか、直せなければ push しない）
- Playwright が入らなかった（`npm i` や `npx playwright install` の失敗）ため、`node test/regression.js` を実行できなかった

毎月1〜6日の起動で一度も終わらなかったときは、6日（最後の起動）の報告の最初に「**今月は未完了**」と書き、何が取れなかったか・どの検査を実行できなかったかを書く。

## 改正が公布されてから e-Gov に載るまで

e-Gov の本文は施行済みの版で、公布から載るまで日がかかる。この間は e-Gov の照合（`paytable`・`values`）は古い条文と比べることになるので、次の公式資料と照合して入れる。

- 衆議院「制定法律」<https://www.shugiin.go.jp/internet/itdb_housei.nsf/html/housei/menu.htm> … 成立した法律の本文（改め文）。`index.html` でも給与法改正の根拠として衆議院の制定法律のページにリンクしている。
- 官報 <https://www.kanpo.go.jp/> … 公布日・法律番号・別表（俸給表）の本文。
- 防衛省「国会提出法案」の新旧対照表。

入れたときは `assets/data/sources.js` の `items[].how` に「官報（令和N年M月D日）・衆議院 制定法律で照合。e-Gov 未掲載」と書き、e-Gov に載った月に `paytable`・`values` で照合し直す。

## 種類ごとの直し方

### 俸給表の差し替え（`assets/data/pay-table.js`）

1. 公布された改正法の別表第二（自衛官俸給表）を手に入れる。
   - 施行済みなら e-Gov。`node tools/egov-check.js paytable` で e-Gov の表とデータを全欄比べられる（差のある号俸を出す）。
   - 公布直後で e-Gov がまだ古いときは、防衛省の「新旧対照表」か官報の表から読む。
2. 145号俸×19列を書き換える。列の並びは改修ガイドの「俸給表の列番号」。号俸がない所は `null`。
3. ファイル冒頭の「（防衛省の職員の給与等に関する法律 別表第二。YYYY年M月公布）」を直し、`index.html` の同じ表記（説明・meta・構造化データ）も直す（`test/check.js` が一致を確かめる）。
4. 号俸の数・列の数が変わったら、`test/check.js` の 145・19 と `PROMOTION_TABLE` も見直す。
5. 照合：e-Gov に載ったら（施行日以後）`node tools/egov-check.js paytable` で差 0 を確かめる。新旧対照表から入れたときは、別の資料（官報・e-Gov）とも突き合わせる。
6. 一般幹部候補生の初任給（`RULES.entry.candidate`）は採用要項の額と号俸の対応なので、新しい採用要項が出たら号俸の対応が変わっていないかを確かめる。

### 昇任の号俸対応表（`assets/data/promotion-table.js`）

施行令 別表第一ロ。`node tools/egov-check.js promotion` で e-Gov と全行比べられる。

### 手当の追加・額の改正（`assets/data/rules.js` の `allowances`）

1. 額・割合だけの改正：該当する値を直し、横のコメントの根拠（条・施行日）を直す。
2. 手当の新設：
   - 金額を入力してもらう手当なら `allowances.manualGroups` に足す（所属で絞るなら `branchOnly`、日額の初期値は `defaultAmount`）。計算のしかたが新しいときだけ `assets/js/allowances.js` を直す。
   - `assets/data/sources.js` の `items` に根拠を足す。
   - 説明文（`index.html`）に手当の説明を足す。
3. 廃止：一覧から消し、説明文の言及も消す。

### 賞与（`bonus`）

- 年間月数 `kimatsuMonths`・`kinbenMonths` と、1回あたりの `kimatsuPer`・`kinbenStandard` を一緒に直す。`test/check.js` は「`kimatsuPer.normal` × 2 ＝ `kimatsuMonths`」を確かめる。
- 勤勉手当の標準の成績率は人事院規則9-40第13条（法律の月数とは別）。規則の改正も確かめる。
- 若年定年退職者給付金で使う月数（`youngPension`）は施行令第24条で別に決まっている。一緒に変わるとは限らない。
- 改正法は「その年の12月期から」と「翌年度から」の2段階で月数が決まることが多い。計算は1年分の月数を使うので、どちらを使うかを説明文に書く。

### 退職手当（`retirement`）

国家公務員退職手当法・同施行令（`taishoku`・`taishokuRei`）の改正を見る。支給率の表、調整率（83.7％）、調整月額を直し、改修ガイドの初期条件の目安（退職手当の額）を新しくする。

### 地域手当

- 本則（`regionalAreas`）は `node tools/egov-check.js values` が人事院規則9-49 別表第一と両方向に照合する（都道府県の「下記以外の地域」の割合、市ごとの割合、表にあってデータにない市）。
- 経過措置（`regionalTransition.byFy`、令和10年3月まで）は e-Gov に載らない。毎年2月ごろ人事院の改正通知（新旧改め文 PDF）で翌年度の表を確かめて足す。
  4月1日になって今の年度の表が `byFy` にないと `test/check.js` が NG にする（令和9年度の表は `assets/data/sources.js` の `pending` にある）。

### 年金・共済・税（e-Gov で照合できない値）

改修ガイドの「毎年の点検チェックリスト」の時期に、それぞれの公式資料で確かめる。4月：日本年金機構（老齢基礎年金の満額・国民年金保険料）、防衛省共済組合（掛金率・子ども・子育て支援金）。3月：税制改正の成立（基礎控除・給与所得控除・税率）。

## 機能全体の点検（毎月）

- `node test/audit/run.js`：計算の大量パターン（入隊区分×所属×予想階級×年齢×昇任期間×退職理由の格子・乱数・単調性で約2万1千件）、退職手当・賞与・退職所得の税の検算（test/audit/law.js の法令の値から独立に計算）、全部の手当と区分の額・重なりのエラー・共有URLの往復・範囲外の入力、画面（幅320〜1920・明暗・印刷・フォーカス・コントラスト）を機械的に調べる。終了コード 0＝異常なし、1＝異常あり（test/audit/result.json に一覧）、2＝道具のエラー。
- 法令の値を直したときは、test/audit/law.js の検算用の値も同じに直す（assets/data/rules.js とは別に書き写してあるので、直し忘れると検算が異常を出す）。
- 法令どおりで「入力を増やすと結果が減る」ことがあるときは、test/audit/mono-exceptions.js に理由つきで足す。

## セキュリティの点検（毎月）

- `node test/security.js`：危ない書き方（eval など）・外部への通信や読み込み・利用者の入力の保存・秘密情報らしき文字列・`target="_blank"` の rel を調べ、共有URLと手当名に HTML・スクリプトを入れて開いても差し込まれない・動かないことを確かめる。終了コード 0 で合格。
- HTML を組み立てる場所（innerHTML など）が増えたり変わったりすると「要レビュー」で NG になる。利用者の入力や共有URLの値をそのまま入れていないか（textContent か esc() を使っているか）をコードで確かめ、安全なら `node test/security.js --accept` で `test/security-sinks.json` を書き換え、理由をコミットに書く。
- あわせて、前回の点検から変わったコード（`git log` と `git diff`）を読み、共有URLの読み込み（`#sim=` の JSON）・入力の検証・CSP・外部への通信を中心に、脆弱性がないかを確かめる。

## 報告に書くこと

- 変えた値（前 → 後）、根拠（法令名・法律番号・条・URL）、施行日
- 確かめたが変わっていなかった範囲
- 勧告・法案だけで、まだ入れていないもの（`assets/data/sources.js` の `pending`）
- 取得できなかった資料と理由
- `node test/check.js` の結果と、コミットのハッシュ
- 未完了の月は「今月は未完了」と、その理由（上の「失敗したときの決まり」）
