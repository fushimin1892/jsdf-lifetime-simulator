# 改正対応の手順書（俸給表・手当・賞与・退職手当）

法令が改正されたときに、決まった順番で直すための手順です。毎月の点検（予定タスク「【毎月】自衛隊シミュの改正チェック」）もこの手順で動きます。
個々の数値がどこにあるかは [AI向け改修ガイド](AI向け改修ガイド.md) の「window.RULES の中身と根拠」を見てください。

## 守ること

- 値は公式資料（e-Gov 法令検索、官報、防衛省の国会提出法案・新旧対照表、人事院、日本年金機構、防衛省共済組合、国税庁）で確かめたものだけを入れる。確かめられないものは入れずに「未確認」と報告する。
- 人事院勧告や国会に出ただけの法案の値は入れない。公布（法律番号が付く）を確かめてから入れる。
- bot 対策でブロックされたサイトを User-Agent の偽装などで回避しない。WebFetch で 403 になる防衛省のページは内蔵ブラウザで読む。取れなければ「取得できなかった」と報告する。
- 外部ライブラリを足さない。利用者の入力を保存・送信するコードを足さない。
- コミットはローカルだけ。push しない。

## 役割の分け方

| 種類 | 場所 | 書くこと |
|---|---|---|
| 数値（データ） | `data/pay-table.js`・`data/promotion-table.js`・`data/rules.js` | 法令の数値だけ。各値の横に根拠の条をコメントで書く |
| 出典 | `data/sources.js`（`window.SOURCES`） | 法令ごとの e-Gov の ID・URL・記録した最新の改正、データの場所ごとの根拠の条と照合日、成立待ちのもの |
| 計算 | `js/` | 計算のしかただけ。数値を書かない（`window.RULES` から読む） |
| 画面の文章 | `index.html` | 説明文の中の数値は自動で変わらないので、数値を変えたら検索して直す |
| 検査 | `test/check.js`（node）・`AI用/検証用スクリプト.js`（ブラウザ） | データの形とつじつま／計算結果の回帰 |
| 照合の道具 | `tools/egov-check.js`（node） | e-Gov の改正日の変化の検出と、俸給表・昇任表の全欄照合 |

`data/sources.js` は画面では読み込みません（サイトの動きは変わりません）。

## 毎回の流れ

1. `git status` がきれいで、main にいることを確かめる。
2. 変化を探す。
   - `node tools/egov-check.js` … e-Gov の最新の改正が `data/sources.js` の記録と違う法令に「★要確認」が出る。
   - 防衛省「国会提出法案」<https://www.mod.go.jp/j/presiding/houan/index.html> … 給与法の改正案の備考に「令和N年法律第N号／公布日」が付いたか。
   - 人事院 <https://www.jinji.go.jp/> … 勧告、人事院規則 9-40（賞与）・9-49／9-49-57（地域手当）などの改正通知。
3. 「★要確認」が出た法令は、改正法令の中身（新旧対照表）を読み、データに関係するかを決める。
   - 関係なければ、`data/sources.js` の `egovRevision` だけ新しい値に書き換える。
   - 関係があれば、下の「種類ごとの直し方」で data を直す。
4. 直したら `data/sources.js` の `items[].checked` をその日にし、`data/rules.js` の `checkedOn` と改修ガイドの「最終更新」を同じ日にする（`test/check.js` が一致を確かめる）。
5. 検査する。
   - `node test/check.js` … NG 0 であること。
   - 画面のファイル（`css/`・`js/`・`data/` の画面で読むもの）を直したときは、`index.html` の `?v=` を全部新しい値にそろえ、ブラウザで `AI用/検証用スクリプト.js` を実行して hash を比べる（改修ガイドの「検証のしかた」）。数値を変えたら hash は変わるので、変わった項目が改正どおりかを確かめ、改修ガイドの hash と初期条件の目安を新しい値にする。
6. 日本語のメッセージでローカルにコミットする（例：「令和8年改正の俸給表と賞与の月数を入れる（令和8年法律第N号）」）。変更がなければコミットしない。

## 種類ごとの直し方

### 俸給表の差し替え（`data/pay-table.js`）

1. 公布された改正法の別表第二（自衛官俸給表）を手に入れる。
   - 施行済みなら e-Gov。`node tools/egov-check.js paytable` で e-Gov の表とデータを全欄比べられる（差のある号俸を出す）。
   - 公布直後で e-Gov がまだ古いときは、防衛省の「新旧対照表」か官報の表から読む。
2. 145号俸×19列を書き換える。列の並びは改修ガイドの「俸給表の列番号」。号俸がない所は `null`。
3. ファイル冒頭の「（防衛省の職員の給与等に関する法律 別表第二。YYYY年M月公布）」を直し、`index.html` の同じ表記（説明・meta・構造化データ）も直す（`test/check.js` が一致を確かめる）。
4. 号俸の数・列の数が変わったら、`test/check.js` の 145・19 と `PROMOTION_TABLE` も見直す。
5. 照合：e-Gov に載ったら（施行日以後）`node tools/egov-check.js paytable` で差 0 を確かめる。新旧対照表から入れたときは、別の資料（官報・e-Gov）とも突き合わせる。
6. 一般幹部候補生の初任給（`RULES.entry.candidate`）は採用要項の額と号俸の対応なので、新しい採用要項が出たら号俸の対応が変わっていないかを確かめる。

### 昇任の号俸対応表（`data/promotion-table.js`）

施行令 別表第一ロ。`node tools/egov-check.js promotion` で e-Gov と全行比べられる。

### 手当の追加・額の改正（`data/rules.js` の `allowances`）

1. 額・割合だけの改正：該当する値を直し、横のコメントの根拠（条・施行日）を直す。
2. 手当の新設：
   - 金額を入力してもらう手当なら `allowances.manualGroups` に足す（所属で絞るなら `branchOnly`、日額の初期値は `defaultAmount`）。計算のしかたが新しいときだけ `js/allowances.js` を直す。
   - `data/sources.js` の `items` に根拠を足す。
   - 説明文（`index.html`）に手当の説明を足す。
3. 廃止：一覧から消し、説明文の言及も消す。

### 賞与（`bonus`）

- 年間月数 `kimatsuMonths`・`kinbenMonths` と、1回あたりの `kimatsuPer`・`kinbenStandard` を一緒に直す。`test/check.js` は「`kimatsuPer.normal` × 2 ＝ `kimatsuMonths`」を確かめる。
- 勤勉手当の標準の成績率は人事院規則9-40第13条（法律の月数とは別）。規則の改正も確かめる。
- 若年定年退職者給付金で使う月数（`youngPension`）は施行令第24条で別に決まっている。一緒に変わるとは限らない。
- 改正法は「その年の12月期から」と「翌年度から」の2段階で月数が決まることが多い。計算は1年分の月数を使うので、どちらを使うかを説明文に書く。

### 退職手当（`retirement`）

国家公務員退職手当法・同施行令（`taishoku`・`taishokuRei`）の改正を見る。支給率の表、調整率（83.7％）、調整月額を直し、改修ガイドの初期条件の目安（退職手当の額）を新しくする。

### 地域手当・年金・共済・税

改修ガイドの「毎年の点検チェックリスト」の時期に、それぞれの公式資料で確かめる（地域手当は毎年2月ごろの人事院規則9-49-57の改正、年金・共済は4月、税は3月の成立）。

## 報告に書くこと

- 変えた値（前 → 後）、根拠（法令名・法律番号・条・URL）、施行日
- 確かめたが変わっていなかった範囲
- 勧告・法案だけで、まだ入れていないもの（`data/sources.js` の `pending`）
- 取得できなかった資料と理由
- `node test/check.js` の結果と、コミットのハッシュ
